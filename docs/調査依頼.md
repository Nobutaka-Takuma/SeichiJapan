# 聖地の調査を依頼するときの指示書

このファイルの「── ここから ──」以下を、そのまま調査担当（別のAIなど）に渡してください。
返ってきた JSON は `npm run intake -- <ファイル>` で点検できます。

点検では、**書かれてきた座標をそのまま信用しません**。Wikidata / OpenStreetMap の
IDから座標を引き直し、食い違えばその場所を弾きます。だから指示書では
「座標を書け」ではなく「**IDを書け**」と求めています。ここがいちばん大事な点です。

---

## ── ここから ──

日本の小説・アニメ・漫画・映画に登場する実在の場所（いわゆる「聖地」）を調べ、
下記の JSON 形式で出力してください。

### 何より大事なこと：場所の特定

**緯度経度を記憶から書かないでください。** 数百メートルずれた座標は、
現地に立つ人を迷わせるので、無いほうがましです。かわりに、
次の識別子のうち**分かるものを書いてください**。座標はこちらで引き直します。

| 欄 | 内容 | 例 |
| --- | --- | --- |
| `wikidata` | Wikidata の項目ID | `"Q11529113"` |
| `osm` | OpenStreetMap の要素 | `"way/123456789"` / `"node/240109189"` |
| `address` | 住居表示レベルの住所 | `"新宿区須賀町5"` |
| `lat` / `lng` | 参考の座標（**任意**） | `35.685321` |

- 上の3つが**ひとつも分からない場合は、その場所を出力しないでください。**
  推測で埋めるより、載っていないほうがよいです。
- `lat` / `lng` は書いても構いませんが、**照合にしか使いません。**
  自信がなければ省いてください。書くなら小数第5位以上（例: `35.68532`）で。
- 場所の広がりに応じて `precision` を選んでください。
  - `point` — 建物・鳥居・踏切・階段など、一点で示せるもの
  - `site` — 境内・公園・駅構内など、敷地全体
  - `area` — 商店街・地区など。座標は代表点になるので、
    `precision_note` に「◯◯通りの中央あたり」と補足してください

### 出してはいけないもの

- **個人の住宅、私有地。** モデルになったとされる家屋も対象外です。
  該当する疑いがあれば `is_private_property: true` を付けてください（取り込みません）。
- 出典を確認できていない「噂」。`evidence: "guess"` にして、
  `uncertainty` に何が不確かかを書くなら構いません。

### 引用について

- `kind: "text"` は**著作権の保護期間が終わった作品の本文引用にだけ**使ってください
  （夏目漱石・芥川龍之介・川端康成など）。
- それ以外はすべて `kind: "scene"` とし、**自分の言葉で場面を要約**してください。
  台詞やナレーションをそのまま書き写さないでください。

### 出典

- `sources` には**実在するURLだけ**を入れてください。思い出せないURLを
  それらしく書くことは、しないでください。空の配列で構いません。
- `evidence: "official"`（公式に明言されている）と書く場合は、
  出典URLが**必須**です。公式サイト、制作委員会の聖地マップ、
  自治体・観光協会の公式ページ、一般社団法人アニメツーリズム協会の認定など。
- `evidence: "research"` は、複数の情報源で一致が取れているもの。
- `evidence: "guess"` は、あなたの推測。`uncertainty` を必ず書いてください。

### 出力する JSON

```json
{

  "pack_id": "0004-例",
  "description": "◯◯周辺の聖地",
  "works": [
    {

      "title": "君の名は。",
      "author": "新海誠",
      "medium": "anime",
      "year": 2016,
      "description": "一行から三行で、どんな作品か。",
      "wikidata": "Q23755697"
    }
  ],
  "places": [
    {
      "name": "須賀神社 男坂",
      "official_name": "須賀神社",
```

### 各欄の決まり

| 欄 | 決まり |
| --- | --- |
| `works[].medium` | `novel` / `anime` / `manga` / `film` のいずれか |
| `works[].slug` | 半角小文字・数字・ハイフン。省略可 |
| `places[].name` | このサイトでの見出し。**同じ場所が別の作品にも出るなら、同じ名前**にしてください（項目が分かれてしまいます）。例:「四ツ谷駅」 |
| `places[].body` | 4000字まで。作品の話だけでなく、**その場所自体の由来や歴史**を書いてください。事典として読まれます |
| `places[].access` | 訪問者向け。「日曜は閉門」「住宅街なので静かに」など実用的なことを |
| `scenes[].quote` | 5〜600字 |
| `scenes[].rationale` | 10字以上。「公式サイトに記載」だけでなく、**照合できる特徴**（建物の形、看板、地形）を書けると強い |

### 分量と優先順位

- 1回の出力で **場所 10〜30件** を目安にしてください。多すぎると精度が落ちます。
- 地域や作品でまとめてください（「◯◯市の聖地」「『△△』の舞台」）。
  ばらばらに集めるより、まとまっているほうが訪問者の役に立ちます。
- **同じ場所に複数の作品が重なるもの**は特に価値があります。見つけたら必ず入れてください。

## 受け取ったあとの手順

```bash
# 1. 点検（書き込みはしない）
npm run intake -- research.json

# 2. 直すべき点を調査担当に戻す。通ったら書き出す
npm run intake -- research.json --write --by research_ai

# 3. 書き出された src/lib/data/packs/<pack_id>.ts に目を通す
# 4. src/lib/data/index.ts の PACKS に加える
# 5. npm run db:setup
```

点検で見ていること:

| 見ている点 | 判定 |
| --- | --- |
| 座標が日本の範囲外（緯度経度の入れ替わりも検出） | ✗ 取り込まない |
| Wikidata / OSM から引いた座標と食い違う | ✗ 取り込まない（許容は point 150m / site 400m / area 1500m） |
| 位置の根拠（wikidata・osm・address）がひとつも無い | ✗ 取り込まない |
| 私有地・個人宅として申告されている | ✗ 取り込まない |
| 保護期間内の作品を逐語引用している | ✗ 取り込まない |
| 「公式」と書いてあるのに出典が無い | ✗ 取り込まない |
| 座標の桁が粗い（小数第3位以下） | △ 警告 |
| すでにある項目の120m以内 | △ 警告（同じ場所なら名前を合わせる） |
| **同じ名前の項目と座標がずれている** | △ 警告（取り込んでも既存の座標は変わらないので、手で直す） |
| 出典が無い | △ 警告 |

外部（Wikidata・OpenStreetMap）に接続できない環境では、照合は「未実施」として
警告に出ます。**黙って通すことはしません。**

### 既存の項目は上書きされません

同じ名前の場所がすでにあると、**その項目には触れず、シーンだけが足されます**。
利用者が書いた記事を調査結果で消してしまわないための決まりです。

裏を返すと、**既存の座標が間違っていても直りません**。そのため、同じ名前で
座標が離れているときは警告を出します。どちらが正しいか確かめて、
新しいほうが正しければ `/places/<id>/edit` から手で直してください。
